# Pear 长期优化路线图

本文档承接 `docs/code-review-remediation-plan.md` 中的 P3 长期优化方向。P0-P2 已优先处理安全、正确性、配置和测试问题；P3 属于后续架构演进，不建议与安全修复混在同一批次中大规模改造。

## 1. DAO 架构

### 当前状态

- CRUD 动态 SQL 已完成第一阶段加固：字段白名单、表名元数据来源约束、MyBatis 参数绑定和输入校验。
- `AdminDAO` 仍然承担 SQL 片段组装和 Mapper 调用，职责偏重。

### 后续任务

1. 抽象 `AdminSqlBuilder`，将 create/query/update/delete 的 SQL 构造从 `AdminDAO` 中拆出。
2. 引入数据库方言接口，例如 `Dialect`、`MysqlDialect`、`SqliteDialect`，统一处理引用符、分页、日期类型和关键字转义。
3. 保留 `SqlQuery` 作为参数化查询载体，禁止回退到值拼接。
4. 为每个 SQL builder 方法补充输入、输出和非法字段测试。

### 验收标准

- `AdminDAO` 只负责调用 mapper，不直接组装复杂 SQL。
- 新增方言无需改 CRUD 主流程。
- SQL 注入回归测试继续通过。

## 2. 事件与钩子

### 当前状态

- 注册、登录和 CRUD 流程中已有注释标明事件发布点，但尚未形成统一事件总线。
- 钩子异常已通过异常处理体系区分 400/401/403/404/500，但业务拒绝和系统错误仍可进一步细分。

### 后续任务

1. 定义事件模型：`UserRegisteredEvent`、`UserLoggedInEvent`、`AdminCrudEvent`。
2. 基于 Spring `ApplicationEventPublisher` 或项目内轻量事件总线发布事件。
3. 增加默认审计订阅器，记录登录、权限拒绝、CRUD 变更。
4. 将钩子异常拆分为业务拒绝、参数错误和系统错误。

### 验收标准

- 业务侧可以订阅注册、登录、CRUD 事件。
- 事件处理失败不破坏主流程，除非订阅器明确声明阻断。
- 审计日志字段稳定，便于后续检索。

## 3. 前端后台

### 当前状态

- 后台接口已对 model 不存在、非法输入和敏感字段响应做安全约束。
- 前端模板仍偏基础，删除确认、批量操作和字段级权限展示还需要增强。

### 后续任务

1. 删除、批量删除、批量更新增加二次确认和操作结果反馈。
2. 表单根据后端元数据渲染 required、readonly、type、select 等规则。
3. 密码相关页面避免明文回显，提交后立即清空输入框。
4. 后台元数据接口按当前用户权限裁剪字段和操作。

### 验收标准

- 危险操作有确认和可追踪反馈。
- 无权限字段不在前端元数据中暴露。
- 密码输入只在用户本地输入框短暂存在，不进入日志或页面回显。

## 4. 可观测性

### 当前状态

- 认证失败、SQL 构造和异常处理已有日志，但日志结构尚未统一。
- 缓存缺少命中率、淘汰次数、容量等指标输出。

### 后续任务

1. 定义结构化日志字段：`event`、`userId`、`model`、`action`、`status`、`requestId`。
2. 为认证失败、权限拒绝、CRUD 变更增加审计日志。
3. 为缓存模板增加可选指标：命中次数、未命中次数、淘汰次数、当前容量。
4. 后续可接入 Micrometer，输出 Prometheus 兼容指标。

### 验收标准

- 关键安全事件可以通过日志字段检索。
- 缓存行为可以通过指标判断是否异常。
- 关闭指标时不影响现有功能。

## 建议拆分顺序

1. `AdminSqlBuilder` 拆分和方言接口。
2. Spring 事件发布与审计订阅器。
3. 后台元数据按权限裁剪。
4. 缓存和 CRUD 指标输出。
5. 前端交互增强。
